# SpendSense Project Day Team Hub

A responsive project showcase and five-profile portfolio hub for SpendSense. It is built as a dependency-free static site so member pages are pre-rendered and open directly on GitHub Pages, including on refresh.

## Run locally

Requirements: Node.js 20 or newer. No package installation is needed.

```sh
npm run dev
```

Open the local URL printed by the server (normally `http://127.0.0.1:4173`). To build only:

```sh
npm run build
npm run check
```

## Pages and deployment

The production build writes the homepage to `dist/index.html`, one static page per developer to `dist/team/<slug>/index.html`, and a GitHub Pages `dist/404.html`. This pre-rendered routing means direct profile links and reloads work without client-side route rewrites.

The GitHub Actions workflow in `.github/workflows/pages.yml` builds with a repository-aware base path, validates the output, and deploys on pushes to `main` or a manual workflow run. In the repository, open **Settings → Pages**, select **GitHub Actions** as the build and deployment source, then allow the workflow to complete. The Pages URL is `https://<owner>.github.io/ProjectDayPortfolioDisplay/` for this project repository. Internal links and assets use the configured base path.

To preview the GitHub Pages subpath locally, run:

```sh
$env:BASE_PATH="/ProjectDayPortfolioDisplay/"
npm run build
npm run check
```

For a root-hosted preview, use the default `/` base path. Do not configure a custom domain or change DNS until the domain and its owner are confirmed.

## Content editing

Public content is maintained in [`src/data/content.js`](src/data/content.js). The build creates all routes from this file and the page templates in `src/template.js`.

### Add a team member

Update one of the five entries generated by `placeholderMember()` with an approved name, stable slug, role, biography, portrait path, skills, project list, professional links and optional public CV PDF. Keep five entries unless the team confirms a different size. Portraits belong in `public/assets/team/`; CVs belong in `public/assets/cvs/`. In `content.js`, use paths relative to `public/`, such as `assets/team/portrait.jpg` and `assets/cvs/member-cv.pdf`. Only use photographs, contact details and CVs approved for public release. Missing links and files are hidden automatically.

### Add a project

Add a project to that member's `projects` array with its title, summary, the developer's actual responsibility, technologies, screenshots and verified repository/demo URLs. Put approved images in `public/assets/projects/`. Project details render from the structured data.

### Confirm features and contributions

The current feature entries are **concepts suggested by the implementation brief**, not a statement that the final app includes them. Verify the app feature list, screenshots and technology choices, then update the relevant entry. Add an item to `contributions` only after the developer and their exact role are confirmed; link using the matching member `id`. The profile contribution sections are derived from these feature mappings so there is one source of truth.

### Add screenshots and CVs

Place approved assets under `public/assets/screenshots/`, `public/assets/projects/`, `public/assets/team/` or `public/assets/cvs/`, then use their path from `public/` in `content.js`. For screenshots, use `{ src: "assets/screenshots/file.png", alt: "Concise description" }`. A CV path enables the inline PDF viewer, open-in-new-tab link and download. The build copies all files under `public/assets/`. A missing asset should never be replaced with an unrelated stock image.

### Update the timeline and links

The current milestone titles are example planning stages with dates and details still pending. Replace them with confirmed events before presenting them as project history. Add the application or source repository URL to `site.applicationUrl` or `site.repositoryUrl` only when the team confirms it is public.

## Current placeholders to replace

- Five profile labels, roles, biographies, portraits, skills, portfolios, professional links and CVs.
- Feature list, approved screenshots, technology details and developer contribution ownership.
- Timeline descriptions, evidence and dates.
- Confirmed public SpendSense application and repository URLs.
- The hero interface is an explicitly labeled CSS illustration, not an application screenshot.

No developer identity, personal project, contact detail, contribution, CV, date, or product statistic has been invented. There is no backend, tracking, analytics, external image dependency, or account system.

For a field-by-field handoff, use [`CONTENT_CHECKLIST.md`](CONTENT_CHECKLIST.md).
