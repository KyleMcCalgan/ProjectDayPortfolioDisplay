# SpendSense content approval checklist

Use this before replacing profile placeholders in `team-members/<name>/profile.env`, editing shared content in `src/data/content.js`, or adding a public asset.

## Each of the five developers

- [ ] Full name and preferred public URL slug
- [ ] Role or professional headline and short approved biography
- [ ] Approved portrait with descriptive alt text
- [ ] Verified skills with project or contribution evidence
- [ ] Two to four personal projects, each with a summary, actual role, technologies, screenshots and verified links
- [ ] Confirmed SpendSense feature ownership and specific responsibility
- [ ] GitHub, LinkedIn, website and/or email links approved for public display
- [ ] Public CV PDF reviewed to remove information the developer does not want published

## SpendSense project

- [ ] Approved product description and current feature list
- [ ] Review the supplied app screenshots and their descriptive alt text
- [ ] Confirmed technology details for each feature
- [ ] Exact contribution mapping for every developer and feature
- [x] Public application URL
- [ ] Public source repository URL, if the team wants to share it
- [ ] Real development milestones, descriptions, dates and optional evidence
- [ ] Approved use of any university, partner or sponsor names and assets

## Before the public Pages deploy

- [ ] Review every public photograph, CV, contact detail, repository and demo URL
- [ ] Remove any concept that is not part of the final application
- [ ] Run `npm run build` and `npm run check`
- [ ] Review the published pages on mobile and desktop
